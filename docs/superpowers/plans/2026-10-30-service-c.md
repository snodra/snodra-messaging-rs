# Service C and Cross-Language Sandbox Implementation Plan (plan 2 of 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust example service C that handles `Shout` and `Reverse`, publishes `TextShouted` and `TextReversed`, logs `GreetingDelivered`, and runs in the compose sandbox next to the Spring Boot services A and B, which call it and log its events.

**Architecture:** `examples/service-c` is a binary crate in the `kraken-messaging-rs` workspace using only the crate's public API from plan 1. The Kotlin `examples-api` gains the six new classes, service A two endpoints and two event handlers, service B one listener. `compose.local.yaml` adds `service-c`; `smoke.sh` covers the new legs.

**Tech Stack:** plan 1 crate; Kotlin examples as in `kraken-messaging/examples`; Docker Compose override in the umbrella.

**Spec:** `docs/superpowers/specs/2026-10-30-rust-crate-and-service-c-design.md`

## Global Constraints

- Wire names: `examples.Shout`, `examples.Reverse`, `examples.TextShouted`, `examples.TextReversed`; fields `text` on replies, `text` and `at` on events (RFC 3339).
- Service C has no HTTP, no health endpoint; env `KRAKEN_SERVICE_NAME=service-c`, `KRAKEN_HUB_ADDRESS`, `KRAKEN_KAFKA_BOOTSTRAP`, `KRAKEN_MONGODB_URI` (database `service-c`), `RUST_LOG` default `info`.
- Log lines: `C: handled Shout text=<t> -> <UPPER> correlationId=<id>`, `C: answered Reverse text=<t> -> <reversed>`, `C: received GreetingDelivered id=<id> name=<name>`; A: `A: sent Shout text=.. -> ..`, `A: asked Reverse text=.. -> ..`, `A: received TextShouted/TextReversed text=.. at=..`; B: `B: received TextShouted/TextReversed text=.. at=..`.
- Ports: A 8091, B 8092 unchanged; C publishes none.
- Branches: `kraken-messaging-rs` `feat/service-c` (after plan 1 merged), `kraken-messaging` `feat/examples-service-c`, umbrella `examples/service-c`; worktrees under `.worktrees/`.
- Commit trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; Kotlin build with the Rancher Desktop Docker env vars; `cargo fmt`/`clippy -D warnings`/`test` green.

## Review Focus

1. **Unicode in `Reverse`**: reversing must be by `char`, not by byte (`"héllo"` → `"olléh"`, no panic). Pinned: Task 1 `reverse_handles_unicode`.
2. **Blank text on A's endpoints**: `POST /shouts {"text":""}` and `GET /reverse/%20` are 400, nothing on the wire. Pinned: Task 2 `blank text is 400`.
3. **C down when A posts**: 503 `NoHandlerException` on `/shouts`, same as the B case. Covered by the existing advice; pinned live in Task 3 step 5.
4. **Mixed-language event order**: A receives `TextShouted` keyed by the original text; two shouts of the same text land in order (same partition). Pinned live in Task 3 smoke (ids checked, order not asserted; documented).
5. **C starts before the hub**: C must retry, not exit. Pinned live in Task 3 step 5 (`docker compose restart hub` with C running) and by plan 1's reconnect tests.
